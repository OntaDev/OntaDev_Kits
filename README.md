# OntaDev Kits

Плагин наборов (киты) для Paper и Spigot 1.16.5 и новее. Работает поверх [OntaDev_Libs](https://github.com/OntaDev/OntaDev_Libs) 0.2.7: оттуда берутся меню, конфиги, база данных и внедрение зависимостей.

Что он умеет, если коротко:

- Набор это снимок всего инвентаря: хранилище, хотбар, броня и вторая рука. Слоты, зачарования, названия и прочие метаданные сохраняются как есть.
- Красивое главное меню со страницами, закреплёнными слотами и разным лоро для каждого состояния набора (доступен, на задержке, уже получен, нет доступа, выключен, вайп).
- Предпросмотр набора перед получением.
- Редактор прямо в игре: содержимое правится в слотах как в сундуке, настройки меняются кнопками. Руками лезть в файлы не обязательно.
- Задержки, одноразовые наборы, права на каждый набор, команды при получении.
- Режим вайпа: можно разом закрыть выдачу всех наборов на нужное время.
- Данные о получениях лежат в БД, так что несколько серверов могут делить одни и те же задержки.
- Внешний вид, раскладка слотов и все тексты вынесены в конфиги.

## Что нужно для работы

- Java 11 и новее.
- Paper или Spigot 1.16.5+ (плагин собран под `api-version: 1.16`).
- `OntaDev_Libs.jar` версии 0.2.7 или выше. Сама библиотека требует LuckPerms, так что он тоже должен стоять.

## Установка

1. Положите `OntaDev_Libs.jar`, LuckPerms и `OntaDev_Kits.jar` в папку `plugins`.
2. Перезапустите сервер.
3. При первом запуске создаются конфиги и один пример набора `starter`. Его можно сразу посмотреть через `/kit` и поправить через `/kitadmin edit starter`.

## Команды для игроков

Основная команда `/kit`, алиасы `/kits`, `/наборы` и `/кит`. Алиасы меняются в `config.yml` в разделе `commands.kit`.

| Команда | Право | Что делает |
|---|---|---|
| `/kit` | `kits.use` | Открывает меню наборов |
| `/kit <набор>` или `/kit получить <набор>` | `kits.use` | Выдаёт набор |
| `/kit получить <набор> <игрок>` | `kits.give` | Выдаёт набор другому игроку без всяких проверок |
| `/kit посмотреть <набор>` | `kits.use` | Открывает предпросмотр |
| `/kit сброс <набор или *> [игрок]` | `kits.admin` | Сбрасывает задержку себе или игроку, `*` значит все наборы |
| `/kit список` | `kits.use` | Показывает список наборов |

Старый порядок аргументов `/kit reset <игрок> [набор]` тоже ещё работает.

## Команды для администраторов

Команда `/kitadmin`, алиас по умолчанию `/кадмин` (настраивается в `commands.admin`). У подкоманд есть русские названия.

| Команда | Право | Что делает |
|---|---|---|
| `/kitadmin create <id> [слот]` | `kits.admin` | Создаёт набор из вашего инвентаря и открывает редактор. Слот меню от 0 до 53, `-1` или пусто значит автоматически |
| `/kitadmin update <набор>` | `kits.admin` | Перезаписывает содержимое набора вашим инвентарём |
| `/kitadmin edit <набор>` | `kits.admin` | Открывает редактор |
| `/kitadmin delete <набор>` | `kits.admin` | Удаляет набор |
| `/kitadmin give <набор> [игрок]` | `kits.give` | Выдаёт набор без проверок |
| `/kitadmin setcooldown <набор> <время>` | `kits.admin` | Ставит задержку: секунды или запись вроде `1d 2h 30m`, `0` убирает задержку |
| `/kitadmin resetcooldown <набор или *> [игрок]` | `kits.admin` | Сбрасывает задержку |
| `/kitadmin wipe on [время]`, `off`, `status` | `kits.admin` | Режим вайпа |
| `/kitadmin reload` | `kits.reload` | Перечитывает конфиги и наборы |

## Права

| Право | По умолчанию | Для чего |
|---|---|---|
| `kits.use` | все | Открывать меню и брать доступные наборы |
| `kits.admin` | оп | Создавать, править, удалять наборы и сбрасывать задержки |
| `kits.give` | оп | Выдавать наборы другим игрокам |
| `kits.reload` | оп | Перезагружать конфиги |
| `kits.bypass.cooldown` | никому | Игнорировать задержку и одноразовость |
| `kits.bypass.permission` | оп | Брать наборы, на которые нет права |
| `kits.bypass.wipe` | оп | Брать наборы во время вайпа |
| `kits.kit.<id>` | никому | Право на конкретный набор, если включён `auto-permission` |

Про `kits.bypass.cooldown` стоит помнить отдельно. Мы специально не даём его даже операторам: иначе у админов задержка просто не работает, и при тестировании кажется, что получения не считаются. Если нужно, выдайте его через LuckPerms.

Право конкретного набора можно задать в редакторе или в поле `permission` в файле набора. Если оно пустое, набор доступен всем. Если в `config.yml` включён `auto-permission`, то для набора без явного права требуется `kits.kit.<id>`.

## Как работает выдача

Перед выдачей набора плагин проверяет по порядку: включён ли набор, есть ли доступ, не идёт ли вайп, не получал ли игрок одноразовый набор, не кончилась ли задержка. Если что-то не так, игрок видит соответствующее сообщение.

Дальше смотрим на место. Если набор целиком не помещается в инвентарь, он не выдаётся, а само получение не засчитывается и задержка не стартует. Это включено по умолчанию (`require-space: true`). Если выключить эту настройку, то при нехватке места лишнее будет падать под ноги игроку, но только пока включён `drop-overflow`.

Предметы кладутся в те же слоты, что были при сохранении набора, если эти слоты свободны (`preserve-slots`). Занятые слоты заменяются обычной раскладкой в первое свободное место.

После выдачи выполняются консольные команды набора (например, `eco give <player> 100`) и в базе фиксируется время получения.

## Меню

### Главное меню

| Что сделать | Что будет |
|---|---|
| ЛКМ по набору | Получить |
| ПКМ по набору | Предпросмотр |
| Shift+ПКМ (админ) | Открыть редактор |
| Shift+ЛКМ (админ) | Включить или выключить набор |
| Кнопка «Новый набор» (админ) | Создать набор из своего инвентаря, id вводится в чате |

Закреплённые за слотом наборы стоят на своём месте на каждой странице. Остальные раскладываются по слотам из `kit-slots` в `menu.yml` и листаются страницами. Кнопка «Закрыть» по умолчанию стоит в слоте 8.

### Предпросмотр

Раскладка у предпросмотра и редактора одинаковая, чтобы было привычно. Слоты считаются с 0 до 53:

- Слоты 2, 3, 4, 5: шлем, нагрудник, поножи, ботинки.
- Слот 6: вторая рука. Если в наборе там пусто (как и с бронёй), показывается голубое стекло «Пусто».
- Слоты с 9 по 44: сетка предметов на 36 клеток. Сначала идёт хотбар (9 по 17), потом хранилище (18 по 44).
- Слот 8: кнопка «Закрыть».
- Слот 45: «К списку наборов», слот 49: «Получить набор», слот 53: список команд набора, если они есть.
- Слот 47: кнопка «Редактировать», видна только игрокам с `kits.admin`.

Все эти слоты настраиваются: броня, рука и начало сетки в `menu.yml` в разделе `preview.slots`, кнопки в `preview.back`, `preview.claim`, `preview.edit`, `preview.close` и так далее.

### Редактор

Содержимое набора правится прямо в слотах, как в сундуке. Shift-клик по предмету в вашем инвентаре кладёт его в первый свободный слот набора (сначала в сетку, потом в броню и руку). Содержимое сохраняется само, когда окно закрывается.

Кнопки по умолчанию:

| Слот | Кнопка |
|---|---|
| 0 | Включить или выключить набор |
| 1 | Описание |
| 7 | Слот в меню (ЛКМ слот, ПКМ порядок при автораскладке) |
| 8 | Закрыть |
| 45 | К списку наборов |
| 46 | Название |
| 47 | Иконка (кликнуть по кнопке предметом с курсора) |
| 48 | Задержка |
| 49 | Одноразовый |
| 50 | Право доступа |
| 51 | Команды |
| 52 | Взять из моего инвентаря (заменяет содержимое набора вашим инвентарём) |
| 53 | Удалить набор (Shift+ЛКМ) |

Текстовые значения вводятся в чате, слово `отмена` выходит без изменений.

## Режим вайпа

Команда `/kitadmin wipe on 2h` закрывает выдачу всех наборов на два часа. Игроки с `kits.bypass.wipe` при этом наборы брать могут. Без времени берётся `wipe.default-seconds` из `config.yml`, а ноль означает «пока не выключат вручную» (`/kitadmin wipe off`).

Во время вайпа всем показывается обратный отсчёт в action bar, а в чат время пишется в моменты из `wipe.broadcast-at` (за час, за полчаса, за минуту и так далее). В меню у наборов появляется отдельное лоро (`lore.wipe` в `menu.yml`).

Состояние вайпа хранится в БД (таблица `kits_wipe`) и переживает перезапуск сервера.

## Несколько серверов и одна база

Настройка лежит в `config.yml`, применяется после рестарта:

```yaml
storage:
  mode: GLOBAL        # GLOBAL: задержки, одноразовые наборы и вайп общие для всех серверов этой БД
                      # LOCAL: у каждого сервера свои (по server-id), но в той же БД
  server-id: server-1 # уникальное имя сервера, важно для LOCAL
  sync-seconds: 30    # как часто подтягивать чужие изменения в GLOBAL, 0 выключает
```

В режиме GLOBAL данные игрока подтягиваются при входе, по таймеру и отдельным запросом прямо перед выдачей набора. Поэтому один и тот же набор нельзя взять на двух серверах одновременно. Вайп в GLOBAL включается и выключается сразу на всех серверах, остальные подхватывают это за время `sync-seconds`.

Сами наборы (файлы в `kits/`) у каждого сервера свои. Если нужны одинаковые наборы везде, синхронизируйте эту папку любым удобным способом.

## Конфиги

Все файлы лежат в `plugins/OntaDev_Kits/`.

| Файл | Что внутри |
|---|---|
| `config.yml` | Поведение: права, сохранение слотов, проверка места, задержка по умолчанию, вайп, алиасы команд, звуки, единицы времени, хранилище |
| `menu.yml` | Внешний вид: заголовки, число рядов, слоты наборов, фон, кнопки, лоро для каждого состояния, раскладка предпросмотра и редактора |
| `messages.yml` | Все сообщения плагина |
| `kits/<id>.yml` | Сами наборы, их можно править вручную, потом `/kitadmin reload` |

Основные настройки `config.yml`:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `auto-permission` | `false` | Требовать `kits.kit.<id>`, если у набора нет своего права |
| `preserve-slots` | `true` | Класть предметы в те же слоты, что при сохранении |
| `drop-overflow` | `true` | Выбрасывать под ноги то, что не влезло (работает, только если `require-space: false`) |
| `require-space` | `true` | Не выдавать набор, если он целиком не помещается |
| `default-cooldown` | `86400` | Задержка для нового набора, секунд |
| `open-menu-on-command` | `true` | Открывать меню по `/kit` без аргументов |
| `auto-update-configs` | `true` | Дописывать новые ключи в конфиги при старте и reload |

При старте и по `/kitadmin reload` в уже существующие `config.yml`, `menu.yml` и `messages.yml` дописываются недостающие ключи из новых версий плагина. Ваши значения при этом не трогаются. Отключается через `auto-update-configs: false`.

Разметка текстов: `<#RRGGBB>`, `&c`, `<bold>`. Плейсхолдеры для названий и описаний наборов: `<name>`, `<id>`, `<description>`, `<cooldown>`, `<remaining>`, `<items>`, `<permission>`, `<commands>`. В заголовке главного меню ещё есть `<page>` и `<pages>`.

Пример файла набора:

```yaml
display-name: "<#34D399>Стартовый набор"
description:
  - "<#CBD5E1>Базовый набор для новичка."
icon: IRON_SWORD
cooldown: 86400      # секунд, 0 значит без задержки
one-time: false
permission: ""
enabled: true
order: 0
slot: -1             # закреплённый слот в меню, -1 значит автоматически
commands:
  - "eco give <player> 100"
items:               # ключ это слот игрока: 0-35 хранилище, 36-39 ботинки..шлем, 40 вторая рука
  '0': { ==: org.bukkit.inventory.ItemStack, type: STONE_SWORD }
```

Раскладка слотов в самом меню (предпросмотр и редактор) от номеров слотов в файле набора не зависит. В файле всегда лежат настоящие слоты инвентаря, а где их показать, решает `menu.yml`.

## Где хранятся данные

Время получения наборов и состояние вайпа лежат в базе через общий `DatabaseManager` из OntaDev_Libs. По умолчанию это H2 в папке библиотеки, для MySQL и PostgreSQL всё настраивается на стороне Libs. Таблицы называются `kits_claims` и `kits_wipe`.

## Сборка

```bash
mvn clean package
```

Готовый jar лежит в `target/OntaDev_Kits.jar`. Нужен `com.ontadev:libs:0.2.7` в локальном Maven-репозитории: его ставит `mvn install` в проекте OntaDev_Libs, либо `mvn install:install-file` с готовым jar.

CI собирает проект на self-hosted раннере и при пуше в `main` создаёт GitHub Release с тегом `v<версия из pom.xml>`, куда прикладывает jar. Раннер берёт библиотеку из своего локального `.m2`, так что сначала должен собраться OntaDev_Libs той же версии.
